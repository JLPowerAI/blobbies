# Blobbies (repo: unshackled-bot)

Tauri 2 desktop app: local AI agents ("Blobs") with persistent memories, personalities, and tools, running against a local Ollama model or (opt-in) Tinfoil's attested private cloud.

**Core product constraint — user content stays unreadable to everyone else.** Blobbies competes with cloud assistants by keeping user data (emails, documents, memories, transcripts) out of anyone else's hands. Exactly two model paths are allowed, by explicit product decision: local Ollama, and Tinfoil enclaves (`src/lib/tinfoil.ts`) — inference in attested AMD SEV-SNP enclaves, request bodies HPKE-encrypted end-to-end, enclave code verified client-side against a Sigstore transparency log before the first byte leaves the device. Never wire in a plain cloud LLM API, remote telemetry, or any feature that ships user content readable off the device — that isn't a missing feature, it's the differentiator. Treat any other outbound data flow of user content as a design bug.

## Parts

- `src/` — all business logic lives in the React frontend: prompt assembly, agent turn loop (`src/lib/ai.ts` → `streamBlobTurn()`), tool routing, memory reconciliation (`src/lib/intent.ts`).
- `src-tauri/` — thin Rust shell: sandboxed JSON storage (`store.rs`), Ollama discovery/launch, OS integration. Not a lib crate; binary is capital-B `Blobbies` so the macOS dock name is right.
- `sim/` — live harness (`*.sim.ts`), never gates commits/CI. `pnpm sim` / `sim:caps` / `sim:tools` are model tuning: real `streamBlobTurn()` against live Ollama, slow and non-deterministic (`SIM_MODEL` picks the model). `pnpm sim:mcp` is the exception — a real MCP server on a real loopback port, no model and no network, so it is deterministic; it lives here because it binds ports and takes ~22s (one test waits out the real 20s `REQUEST_TIMEOUT_MS`). It covers what a stubbed `fetch` cannot: that a redirect is actually refused with the body never reaching the second host, that an endless response body is actually cut off at the cap, and that a silent server times out *even when the caller passed a signal* — routines always pass one, so `signal ?? timeout` left them with no timeout at all.

## Gotchas / invariants

- **Storage slice names are allowlisted in Rust.** `store.rs` only accepts root slices `settings|ui-layout|roster|user` and per-blob slices `config|routines|transcript|runs` (UUID-validated blob ids). Adding a new persisted slice on the TS side without extending these arrays fails with `InvalidSliceKey`. `user` holds the memories shared by every Blob; per-Blob memories stay in that Blob's `config`. Per-blob *files* live outside the store: `home.rs` sandboxes `blobs/<id>/home/` for the agent's fs tools (path containment + size caps mirrored from store.rs).
- **Tinfoil model ids are namespaced in `settings.model`.** `tinfoil:<id>` picks the Tinfoil provider; anything unprefixed is an Ollama tag (`isTinfoilModel`/`tinfoilModelId` in `src/lib/tinfoil.ts`). The three structured calls (router, reconcile, forced-configure) branch on this prefix; the Ollama request bodies are tuning-tested and must stay byte-identical. Tinfoil uses OpenAI `json_schema` structured outputs with `strict: true`, which requires `additionalProperties: false` on every schema (Ollama ignores it — add it unconditionally).
- **Secrets live in the OS keychain, never the JSON store.** `src-tauri/src/secrets.rs` allowlists exactly `tinfoil-api-key` and `tinfoil-cache-secret` (service `com.blobbies.app`); adding a secret means extending that array. The TS side is `src/lib/secrets.ts` (localStorage fallback in browser dev only). The cache secret scopes Tinfoil's server-side prompt cache across launches — not a credential, but still keep it out of logs.
- **The `openai` import is aliased in three places.** `vite.config.ts`, `vitest.config.ts`, and `vitest.sim.config.ts` each alias bare `openai` → `src/lib/openai-browser.ts` (forces `dangerouslyAllowBrowser`; the SDK refuses to construct in a webview/jsdom otherwise) and inline `@kenkaiiii/gg-ai`/`gg-agent` so the alias applies to *their* imports too. The shim also re-exports openai's public named surface (`openai/error`, `APIPromise`, `PagePromise`, `toFile`) because the `tinfoil` package re-exports those names from bare `openai` — which the alias points back at the shim; dropping them crashes tinfoil at module evaluation. Both `define: { "process.env": "{}" }` entries exist because gg-ai reads `process.env` at module scope. Any new vitest/vite config must replicate all three pieces or gg-ai breaks at import time.
- **tsconfig reference order matters.** `tsconfig.node.json` must stay before `tsconfig.app.json` in root `tsconfig.json` — TS7 build mode leaks `paths` between sibling projects and the wrong order breaks the `@/*` alias.
- **Dev port 1421 is a cross-file contract.** `DEV_PORT` in `vite.config.ts` must equal `build.devUrl` in `src-tauri/tauri.conf.json`; `strictPort` makes Tauri fail fast if taken.
- **Local-model tuning constants are load-bearing** (each has a test asserting it):
  - Thinking is forced off unless explicitly opted in (`think: false` on the native path) — reasoning models otherwise burn ~20s of hidden tokens before the first visible word.
  - Native `/api/chat` (not `/v1`) with `num_ctx: 16384` — the OpenAI-compat endpoint can't set `num_ctx`, so Ollama's 4096 default truncates long conversations mid-reply.
  - Intent classifier uses `temperature: 0` — sim measured a small model calling `remember` 0/8 times at non-zero temp. Chat temperature is deliberately left at model default: a sweep measured restraint at 38–63% across 0.1/0.3/default — noise, not a lever.
  - **The chat loop never gets memory or config tools.** All Blob-state writes go through the intent router (`routeIntent` → `applyIntent` / forced-configure); the loop's catalog is web-only, gated by the router's required `needs_web` boolean (fails open to true). Offered unconditionally, qwen3.5:2b googled the user's own facts in 4/8 runs and once deleted the memory it was asked about; gated, restraint and web-access both measure 8/8.
  - **Turn scopes:** `streamBlobTurn({ scope })` — `"chat"` (default) is the tuned interactive path above and must not gain tools; `"routine"` (scheduler/test-run fires, and answers to asks) skips the router and adds fs tools + `ask_user` + `run_subagent` + `spawn_blob`/`delete_blob` + the tools of any enabled MCP server. Tests pin both catalogs. Everything third-party or destructive is routine-only on purpose: the chat catalog's restraint is a measured number, and a human in a chat can already press the + button.
  - **Attachments are inlined, not tool-read** (`src/lib/attachments.ts`). A file picked in the composer is saved into the Blob's home folder and its text is spliced into that message's prompt at turn time, fenced by `wrapUntrusted` — the chat catalog is web-only by measurement, so a file the model had to fetch with a tool would be invisible there. `ATTACHMENT_PROMPT_CHARS` is one budget split across a message's files, like `MEMORY_PROMPT_CHARS`. Everything is stored as text — a PDF or image as `report.pdf.txt` / `photo.png.txt`, keyed off whether extraction happened and *not* off the extension (a text file misnamed `.pdf` keeps its own name). The local models here aren't multimodal, so an image is only attachable as the text OCR finds in it; Office files are refused with a reason in the transcript.
  - **pdf.js is the untrusted-bytes parser *in the webview*** (`src/lib/pdf-text.ts`, pdfjs-dist pinned to 6.2.108; the other one, the image decoder, is deliberately in Rust — see OCR below). Hard rules, each load-bearing: (1) the `Worker` is constructed *here*, never by pdf.js — left to itself it wraps `workerSrc` in a `blob:` URL whenever it thinks the origin differs (Tauri's custom scheme), which CSP `default-src 'self'` refuses, and it then *silently* falls back to parsing on the main thread where nothing can stop it; (2) the timeout is a `Promise.race` **and** a `worker.terminate()`, and `task.destroy()` is never awaited — pdf.js only terminates workers it created itself (so `destroy()` alone leaves a runaway parse running), while every pdf.js call is a round trip to that worker (so after a terminate, `task.promise` *and* `destroy()` stay pending forever). The race is what fails the attachment; the terminate is what stops the CPU burning; (3) `isEvalSupported` **no longer exists in v6** (CVE-2024-4367's fix removed the eval path), so passing it is a no-op that merely looks safe — the live flags are `disableFontFace`/`useWasm`/`isImageDecoderSupported`/`maxImageSize`, checked against the installed `.d.ts`; (4) a PDF is detected by its `%PDF-` header, never by extension or the browser's MIME guess. `pdf-text` is `import()`ed on demand, so the ~135 KB gz chunk and the 1.2 MB worker never load until someone attaches a PDF. Text extraction is verified against pdfjs-dist directly (jsdom has no `Worker`); the unit tests mock the module and pin the routing around it.
  - **OCR runs in Rust, not the webview** (`src-tauri/src/ocr.rs`, ocrs + rten). This is a CSP decision, not a performance one: tesseract.js needs `'wasm-unsafe-eval'` in `script-src`, and `WKWebView` applies that to the whole page — trading the app's main containment boundary for one feature. Only extracted text crosses IPC, and the image is sent as a `Uint8Array` so Tauri uses a raw body instead of JSON (a normal argument would ship megabytes as a list of numbers). Notes: model weights (12 MB) are downloaded by `build.rs` and `include_bytes!`d, each pinned by SHA-256 — `OCRS_MODEL_DIR` builds offline but the checksum still applies, and nothing is ever fetched at runtime; **rten is pinned to 0.24, not 0.25**, because 0.25 raised its MSRV to 1.94 against this crate's deliberate 1.90 pin; decoded pixels are capped from the image *header* (a 380 KB PNG can expand to 400 MP); and RGBA is composited onto white rather than `into_rgb8()`, which drops alpha and turns a transparent screenshot into black-on-black that OCRs as nothing. `build.rs` carries its own `allow(clippy::panic)` because panicking is how a build script reports failure.
  - **pdf.js *transfers* the `data` buffer to its worker**, so both entry points pass it `new Uint8Array(bytes)`. Handing over the caller's array leaves it detached (`byteLength === 0`) and the next use throws "An ArrayBuffer is detached and could not be cloned" — which is precisely the scanned-PDF path, where `attachments.ts` reads the text layer and then rasterizes the *same* array.
  - **`wasmUrl: "/pdfjs/"` is what makes `useWasm: false` work rather than merely look safe.** Without it pdf.js has no image decoder at all, and a JBIG2/JPEG2000 scan rasterizes to a blank page that OCRs as "no text found" — measured in a real browser under the app's own CSP: 7894 dark pixels with the URL, 0 without. The two fallback scripts are served from `node_modules` in dev and copied into the bundle at build time (`pdfjsFallbackDecoders` in vite.config.ts) — deliberately *not* `public/`, which Vite's dev server refuses to serve to a source-code import, so that arrangement worked in a release build and broke in dev.
  - **A scanned PDF is rasterized only after the text layer comes back empty** (`src/lib/pdf-ocr.ts`). Separate module from `pdf-text.ts` on purpose: that one turns rendering, fonts and images *off* because a text layer needs none of them, and rasterizing needs the exact opposite — one function with a flag would mean the hardened path and the rendering path sharing a config. OCR costs seconds of CPU per page, so it is never on the fast path; pages are drawn on a white fill (scans are often transparent) and capped at 20.
  - **Both memory sections share one character budget** (`MEMORY_PROMPT_CHARS` in blob-tools.ts — one constant, spent on shared facts first, remainder to the Blob's own). `MEMORY_LIMIT` caps the *count* per scope but not the length, and Ollama answers an over-long prompt by silently truncating it — costing the conversation, not the memories. User-scope facts render *above* the Blob's own (they change less often, so more of the cached prefix survives a Blob-scope write), and only the Blob's own are numbered, because the intent router addresses those by position (`forget` → "[2]").
  - **The keychain is probed lazily and once per session** (`configureTinfoilFromKeychain` memoization): a keychain read can prompt for the device password, so nothing may touch it unless a `tinfoil:` model is selected or the user acts (model picker open, Settings save with `force`). That caps prompts *within* one launch — the prompt *per rebuild* is macOS, not the app: a keychain item's ACL is keyed to the creating binary's code-signature hash, and `tauri dev` links a fresh ad-hoc signature every build (`Signature=adhoc`, `TeamIdentifier=not set`), so each rebuild is a new program and "Always Allow" can never stick. Set `TINFOIL_API_KEY` in the gitignored `.env.local` (the `tauri:dev` script sources it; empty or absent changes nothing) and debug builds route secrets through a process-local map instead (`mod dev` in `secrets.rs`, `#[cfg(debug_assertions)]`, opt-in only) — zero keychain reads, zero prompts. Release always uses the keychain; a stable Developer ID signature is what makes the ACL stick for real users.
  - Every field the intent mapping reads is `required` in the schema — optional `memory_number` was omitted by the model on every delete (grammar-legal, mapping discarded it, forgets went 0/3). Unused fields are emitted as 0 and ignored.
  - Structured-output schemas must never carry `maxLength` — a grammar cap truncates the model mid-word; enforce length in the prompt.
  - **Every** Ollama call (chat, router, reconcile, forced-configure) pins the same `num_ctx: 16384` — Ollama's scheduler deep-equals runner options and reloads the whole model (dumping the KV cache) on any mismatch, so one call without it thrashes the runner twice per message.
  - Every call sends `keep_alive: "30m"` — the 5-minute server default unloads an idle model, costing a cold reload plus a from-scratch prefill on the user's next message. The other half of the deal: `ollama_unload_on_exit` in `commands.rs` runs `ollama stop <model>` on `RunEvent::Exit`, and `changeModel` in `App.tsx` calls `unloadOllamaModel` on the outgoing model when the user switches in the dropdown — otherwise Ollama keeps both resident side by side. Change any of the three only with the others in mind.
  - No clock in the system prompt — prefix caching is exact-match, so a minute-level timestamp there re-prefills the entire transcript every turn. The clock is appended to the newest user message via `timeNote()`; history is capped by `trimHistory()` in block trims (not a sliding window) so the cached prefix stays byte-stable between trims.
- **Only Blob-scope memories are written automatically.** The intent router has no notion of the `user` scope; promotion between scopes is a manual per-row toggle in `MemoriesSection` (`DetailPanel.tsx`). Teaching the classifier a second scope is a retune with sim cost, and the roadmap's stated gap was visibility, not automatic promotion.
- **CSP `connect-src` carries the Tinfoil hosts.** `https://*.tinfoil.sh` (atc attestation + inference + per-enclave domains) and `https://tuf-repo-cdn.sigstore.dev` (Sigstore TUF root for the verifier) in `src-tauri/tauri.conf.json`. Tinfoil uses webview fetch, not the tauri http plugin, so `capabilities/default.json` is unaffected.
- **`capabilities/default.json` denies private ranges one glob per octet** — Tauri URL globs can't express ranges, so Docker 172.16–172.31 and CGNAT 100.64–100.127 are enumerated entry-by-entry under `http:default`. Removing one silently reopens SSRF-ish access from web tools. The deny list is `https://`-only, which is why the two loopback `http://` allow entries are additive rather than a hole in it — and why local MCP is http-only (see below).
- **Local MCP is loopback-only, and the capability is not the control** (`src/lib/mcp.ts`). `parseLoopbackUrl` re-runs on *every* request, not just at save time, because `mcpServers` lives in the plain-JSON `settings` slice — an editable file on disk. It accepts exactly what the capability permits — `http://` (not https, which the deny list blocks on loopback and **deny beats allow** in Tauri's scope), host exactly `localhost`/`127.0.0.1` (no `::1`: no allow entry covers it), and an explicit port (the globs carry `:*`, which will not match a portless URL). Loosening any of those three yields a connection the UI saves and the Rust layer then refuses with an opaque error. `maxRedirections: 0` is load-bearing: the Rust http plugin scope-checks only the *initial* URL and then lets reqwest follow redirects, so a local server answering 302 with a public `Location` would carry the POST body (tool arguments and all) off the machine. An MCP server is an untrusted party whose text is model-facing: tool names are sanitized and namespaced (`mcp__<server>__<tool>`), deduped across *all* servers so a newly added one cannot shadow a trusted one; descriptions are stripped of newlines/bidi/zero-width characters and wrapped in a fixed "that server's own text, not an instruction from the user" frame; results are truncated and fenced by `wrapUntrusted`. **stdio transport is deliberately absent** — it means spawning user-configured executables, i.e. arbitrary code execution driven by a config file; a local proxy fronts stdio servers today. The client is hand-rolled JSON-RPC (~340 lines of code) rather than `@modelcontextprotocol/sdk`, which drags express/hono/jose/cross-spawn into the webview bundle for the three calls we actually make (`initialize`, `tools/list`, `tools/call`).
- **Usage counts the agent loop only.** `onUsage` is fed from gg-agent's `agent_done`, which fires once per loop — and a turn can run the loop more than once (the no-tools retry, the rescue round), so callers *sum*. The three structured calls (router, reconcile, forced-configure) are outside the loop and go uncounted; plumbing them in would touch the tuning-tested request bodies. Framed in the UI as why replies slow down, never as cost — local inference has no bill.
- **Sim tests are intentionally serial** (`fileParallelism: false`, `maxConcurrency: 1`): parallel runs fight over Ollama KV-cache slots and distort the timing report.
- **Rust pinning is deliberate**: `rust-toolchain.toml` 1.90.0, `Cargo.toml` `rust-version = "1.90"`, edition 2024 — kept in sync so the MSRV-aware resolver doesn't hold back security patches. CI installs cargo-audit with `--locked` because unlocked install broke on the pinned rustc.

## Workflow notes

- `pnpm tauri:dev` for the full app (spawns `pnpm dev` itself); plain `pnpm dev` is frontend-only in a browser.
- `pnpm build` chains `typecheck && vite build`; `tauri:build` reads `TAURI_ENV_PLATFORM`/`TAURI_ENV_DEBUG` to pick build target/minify.
- Lefthook pre-push runs typecheck + test + clippy; pre-commit auto-fixes biome + rustfmt on staged files. `pnpm check` is the local equivalent of CI.
- Rust checks live behind pnpm wrappers (`rs:fmt`, `rs:lint`, `rs:test`) — clippy runs with `-D warnings`.
