# Blobbies (repo: unshackled-bot)

Tauri 2 desktop app: local AI agents ("Blobs") with persistent memories, personalities, and tools, running against a local Ollama model or (opt-in) Tinfoil's attested private cloud.

**Core product constraint — user content stays unreadable to everyone else.** Blobbies competes with cloud assistants by keeping user data (emails, documents, memories, transcripts) out of anyone else's hands. Exactly two model paths are allowed, by explicit product decision: local Ollama, and Tinfoil enclaves (`src/lib/tinfoil.ts`) — inference in attested AMD SEV-SNP enclaves, request bodies HPKE-encrypted end-to-end, enclave code verified client-side against a Sigstore transparency log before the first byte leaves the device. Never wire in a plain cloud LLM API, remote telemetry, or any feature that ships user content readable off the device — that isn't a missing feature, it's the differentiator. Treat any other outbound data flow of user content as a design bug.

## Parts

- `src/` — all business logic lives in the React frontend: prompt assembly, agent turn loop (`src/lib/ai.ts` → `streamBlobTurn()`), tool routing, memory reconciliation (`src/lib/intent.ts`).
- `src-tauri/` — thin Rust shell: sandboxed JSON storage (`store.rs`), Ollama discovery/launch, OS integration. Not a lib crate; binary is capital-B `Blobbies` so the macOS dock name is right.
- `sim/` — live harness (`*.sim.ts`), never gates commits/CI. `pnpm sim` / `sim:caps` / `sim:tools` / `sim:group` are model tuning: real `streamBlobTurn()` against live Ollama, slow and non-deterministic (`SIM_MODEL` picks the model, `SIM_RUNS` repeats each scenario to show flakiness rather than luck). `sim:group` is the group-chat scorecard — selection (only the relevant Blob answers), cross-talk, awareness (a quiet Blob still reads everything), shared memory, addressing, restraint (`PASS`), and both chorus modes. 9/9 on qwen3.5:9b; 2b is weaker at restraint and addressing (~50%), so it is the model to test a prompt change against. The `@everyone` scenario is the one that pulls against the others: every member must answer AND none may parrot, so a prompt change that fixes restraint often breaks it. `pnpm sim:mcp` is the exception — a real MCP server on a real loopback port, no model and no network, so it is deterministic; it lives here because it binds ports and takes ~22s (one test waits out the real 20s `REQUEST_TIMEOUT_MS`). It covers what a stubbed `fetch` cannot: that a redirect is actually refused with the body never reaching the second host, that an endless response body is actually cut off at the cap, and that a silent server times out *even when the caller passed a signal* — routines always pass one, so `signal ?? timeout` left them with no timeout at all.

## Gotchas / invariants

- **Storage slice names are allowlisted in Rust.** `store.rs` only accepts root slices `settings|ui-layout|roster|user|groups`, per-blob slices `config|routines|transcript|runs`, and the group slice `groups/<uuid>/transcript` (UUID-validated ids). Adding a new persisted slice on the TS side without extending these arrays fails with `InvalidSliceKey`. `user` holds the memories shared by every Blob; per-Blob memories stay in that Blob's `config`. Per-blob *files* live outside the store: `home.rs` sandboxes `blobs/<id>/home/` for the agent's fs tools (path containment + size caps mirrored from store.rs).
- **Tinfoil model ids are namespaced in `settings.model`.** `tinfoil:<id>` picks the Tinfoil provider; anything unprefixed is an Ollama tag (`isTinfoilModel`/`tinfoilModelId` in `src/lib/tinfoil.ts`). The three structured calls (router, reconcile, forced-configure) branch on this prefix; the Ollama request bodies are tuning-tested and must stay byte-identical. Tinfoil uses OpenAI `json_schema` structured outputs with `strict: true`, which requires `additionalProperties: false` on every schema (Ollama ignores it — add it unconditionally).
- **Secrets live in the OS keychain, never the JSON store.** `src-tauri/src/secrets.rs` allowlists exactly `tinfoil-api-key` and `tinfoil-cache-secret` (service `com.blobbies.app`); adding a secret means extending that array. The TS side is `src/lib/secrets.ts` (localStorage fallback in browser dev only). The cache secret scopes Tinfoil's server-side prompt cache across launches — not a credential, but still keep it out of logs.
- **Two import aliases are replicated in three places** (`vite.config.ts`, `vitest.config.ts`, `vitest.sim.config.ts`), each with `optimizeDeps.exclude`/`server.deps.inline` for `@kenkaiiii/gg-ai`/`gg-agent` so the aliases apply to *their* imports too; `vite.config.ts` and `vitest.sim.config.ts` additionally need `define: { "process.env": "{}" }` (gg-ai reads `process.env` at module scope; plain vitest runs under Node, which has `process`). Any new vite/vitest config must replicate these or gg-ai breaks at import time.
  - `openai` → `src/lib/openai-browser.ts`: forces `dangerouslyAllowBrowser` (the SDK refuses to construct in a webview/jsdom otherwise). The shim also re-exports openai's public named surface (`openai/error`, `APIPromise`, `PagePromise`, `toFile`) because the `tinfoil` package re-exports those names from bare `openai` — which the alias points back at the shim; dropping them crashes tinfoil at module evaluation.
  - `@anthropic-ai/sdk` → `src/lib/anthropic-stub.ts`: gg-ai statically imports the SDK for its Anthropic provider, which Blobbies can never select (Ollama + Tinfoil only); without the stub its ~100 KB minified lands in the startup bundle. gg-ai touches `Anthropic` only inside its provider factory, so the throwing stub is inert unless an anthropic model is somehow requested.
- **The provider stack is a lazy chunk; the startup chunk has a budget.** UI modules (`App.tsx`, `ChatPane`, `SettingsModal`, `SettingsPanel`, `DetailPanel`) must not statically import values from `@/lib/ai`, `@/lib/tinfoil`, `@/lib/intent`, `@/lib/blob-tools`, or `@kenkaiiii/*` — that pulls gg-ai + the OpenAI SDK + zod + Tinfoil (~570 KB minified) back into the first-paint chunk. The static-safe surface is the leaf modules `tinfoil-model.ts` (id helpers), `prompt.ts` (system prompt / timeNote / trimHistory), and `memory.ts` (limits, `BlobMemory`, `renderMemories`); heavier use goes through dynamic `import()` (`loadAi`/`loadIntent`/`loadTinfoil` in App.tsx, inline elsewhere). `pnpm build` enforces this via `scripts/bundle-budget.mjs` (startup `index-*.js` ≤ 185 kB gzip; measured 168).
- **tsconfig reference order matters.** `tsconfig.node.json` must stay before `tsconfig.app.json` in root `tsconfig.json` — TS7 build mode leaks `paths` between sibling projects and the wrong order breaks the `@/*` alias.
- **Dev port 1421 is a cross-file contract.** `DEV_PORT` in `vite.config.ts` must equal `build.devUrl` in `src-tauri/tauri.conf.json`; `strictPort` makes Tauri fail fast if taken.
- **Local-model tuning constants are load-bearing** (each has a test asserting it):
  - Thinking is forced off unless explicitly opted in (`think: false` on the native path) — reasoning models otherwise burn ~20s of hidden tokens before the first visible word.
  - Native `/api/chat` (not `/v1`) with `num_ctx: 16384` — the OpenAI-compat endpoint can't set `num_ctx`, so Ollama's 4096 default truncates long conversations mid-reply.
  - Intent classifier uses `temperature: 0` — sim measured a small model calling `remember` 0/8 times at non-zero temp. Chat temperature is deliberately left at model default: a sweep measured restraint at 38–63% across 0.1/0.3/default — noise, not a lever.
  - **The chat loop never gets memory or config tools.** All Blob-state writes go through the intent router (`routeIntent` → `applyIntent` / forced-configure); the loop's catalog is web-only, gated by the router's required `needs_web` boolean (fails open to true). Offered unconditionally, qwen3.5:2b googled the user's own facts in 4/8 runs and once deleted the memory it was asked about; gated, restraint and web-access both measure 8/8.
  - **Turn scopes:** `streamBlobTurn({ scope })` — `"chat"` (default) is the tuned interactive path above and must not gain tools (a group turn is a chat turn, so groups add none either); `"routine"` (scheduler/test-run fires, answers to asks, and Blob→Blob hand-offs) skips the router and adds fs tools + `ask_user` + `run_subagent` + `spawn_blob`/`delete_blob`/`message_blob` + the tools of any enabled MCP server. Tests pin both catalogs. Everything third-party or destructive is routine-only on purpose: the chat catalog's restraint is a measured number, and a human in a chat can already press the + button or @-mention the Blob they want.
  - **`message_blob` is the asynchronous hand-off** (`makeRosterTools` + `handOff` in App.tsx): the request is posted as a visible event line in the *receiving* Blob's own conversation and wakes a routine turn there, and the sender's turn moves on — it never sees the reply, which the tool description and the prompt both say twice because a model that waits will invent one. Four guards, each with a test: the receiver's prompt is `wrapUntrusted`-fenced (`blob:<Name>`) since another Blob's words are model output that may be echoing a web page; one send per target per turn, deduped in the per-turn catalog closure, so a retried round is not three nudges; the `run_subagent` helper's catalog does *not* carry it (a helper that could wake Blobs would put a whole chain behind a tool call the user never sees); and `MAX_HANDOFF_HOPS` (3, in App.tsx — importing a value from blob-tools would breach the startup budget) caps the chain, because turns are serial against one local model and two Blobs passing work back would pin it. Stop is the other half: `queuedTurnEpoch` is bumped by `stopTurn` and checked by every turn a turn queued behind itself — the rest of a group's members, a hand-off yet to wake — since the abort signal only reaches whoever is already speaking, so without it Stop leaves the queue running in a conversation the user is not even looking at.
  - **Attachments are inlined, not tool-read** (`src/lib/attachments.ts`). A file picked in the composer is saved into the Blob's home folder and its text is spliced into that message's prompt at turn time, fenced by `wrapUntrusted` — the chat catalog is web-only by measurement, so a file the model had to fetch with a tool would be invisible there. `ATTACHMENT_PROMPT_CHARS` is one budget split across a message's files, like `MEMORY_PROMPT_CHARS`. Everything is stored as text — a PDF or image as `report.pdf.txt` / `photo.png.txt`, keyed off whether extraction happened and *not* off the extension (a text file misnamed `.pdf` keeps its own name). The local models here aren't multimodal, so an image is only attachable as the text OCR finds in it; Office files are refused with a reason in the transcript.
  - **pdf.js is the untrusted-bytes parser *in the webview*** (`src/lib/pdf-text.ts`, pdfjs-dist pinned to 6.2.108; the other one, the image decoder, is deliberately in Rust — see OCR below). Hard rules, each load-bearing: (1) the `Worker` is constructed *here*, never by pdf.js — left to itself it wraps `workerSrc` in a `blob:` URL whenever it thinks the origin differs (Tauri's custom scheme), which CSP `default-src 'self'` refuses, and it then *silently* falls back to parsing on the main thread where nothing can stop it; (2) the timeout is a `Promise.race` **and** a `worker.terminate()`, and `task.destroy()` is never awaited — pdf.js only terminates workers it created itself (so `destroy()` alone leaves a runaway parse running), while every pdf.js call is a round trip to that worker (so after a terminate, `task.promise` *and* `destroy()` stay pending forever). The race is what fails the attachment; the terminate is what stops the CPU burning; (3) `isEvalSupported` **no longer exists in v6** (CVE-2024-4367's fix removed the eval path), so passing it is a no-op that merely looks safe — the live flags are `disableFontFace`/`useWasm`/`isImageDecoderSupported`/`maxImageSize`, checked against the installed `.d.ts`; (4) a PDF is detected by its `%PDF-` header, never by extension or the browser's MIME guess. `pdf-text` is `import()`ed on demand, so the ~135 KB gz chunk and the 1.2 MB worker never load until someone attaches a PDF. Text extraction is verified against pdfjs-dist directly (jsdom has no `Worker`); the unit tests mock the module and pin the routing around it.
  - **`[profile.dev.package."*"] opt-level = 3` is load-bearing for OCR.** Unoptimized, `ocrs`/`rten`/`image` run ~30x slower — measured on one 800x229 image: 4.4s in a debug build, 150ms optimized — which made every `tauri:dev` attachment feel broken. Only dependencies are optimized, so our own crate keeps its fast incremental rebuilds and usable backtraces; the cost is one slow build after a clean checkout. Measured and rejected alongside it: sending raw RGBA instead of PNG over IPC (PNG encode is 10ms against a 7.5 MB vs 463 KB payload), OCR'ing pages concurrently (1.6x on 14 cores — ocrs already parallelizes internally), and reusing the pdf.js worker (33ms, not worth losing terminate-on-timeout).
  - **OCR runs in Rust, not the webview** (`src-tauri/src/ocr.rs`, ocrs + rten). This is a CSP decision, not a performance one: tesseract.js needs `'wasm-unsafe-eval'` in `script-src`, and `WKWebView` applies that to the whole page — trading the app's main containment boundary for one feature. Only extracted text crosses IPC, and the image is sent as a `Uint8Array` so Tauri uses a raw body instead of JSON (a normal argument would ship megabytes as a list of numbers). Notes: model weights (12 MB) are downloaded by `build.rs` and `include_bytes!`d, each pinned by SHA-256 — `OCRS_MODEL_DIR` builds offline but the checksum still applies, and nothing is ever fetched at runtime; **rten is pinned to 0.24, not 0.25**, because 0.25 raised its MSRV to 1.94 against this crate's deliberate 1.90 pin; decoded pixels are capped from the image *header* (a 380 KB PNG can expand to 400 MP); and RGBA is composited onto white rather than `into_rgb8()`, which drops alpha and turns a transparent screenshot into black-on-black that OCRs as nothing. `build.rs` carries its own `allow(clippy::panic)` because panicking is how a build script reports failure.
  - **Never async-iterate a `ReadableStream` — WebKit has not shipped it.** `for await (const x of stream)` throws `undefined is not a function (near '...value of readableStream...')` in `WKWebView`, which is the only engine this app ships on; always `getReader()` (as `mcp.ts` and `ollama-native.ts` already do). This is why `pdf-text.ts` reads `page.streamTextContent()` by hand instead of calling `page.getTextContent()` — that convenience wrapper async-iterates internally, so *every* PDF failed in the app while passing in Chrome and in tests. Async *generators* are fine; it is specifically `ReadableStream[Symbol.asyncIterator]`. Note that Playwright's bundled WebKit is newer than the system one and does have it — to reproduce, `delete ReadableStream.prototype[Symbol.asyncIterator]` first.
  - **pdf.js *transfers* the `data` buffer to its worker**, so both entry points pass it `new Uint8Array(bytes)`. Handing over the caller's array leaves it detached (`byteLength === 0`) and the next use throws "An ArrayBuffer is detached and could not be cloned" — which is precisely the scanned-PDF path, where `attachments.ts` reads the text layer and then rasterizes the *same* array.
  - **`wasmUrl: "/pdfjs/"` is what makes `useWasm: false` work rather than merely look safe.** Without it pdf.js has no image decoder at all, and a JBIG2/JPEG2000 scan rasterizes to a blank page that OCRs as "no text found" — measured in a real browser under the app's own CSP: 7894 dark pixels with the URL, 0 without. The two fallback scripts are served from `node_modules` in dev and copied into the bundle at build time (`pdfjsFallbackDecoders` in vite.config.ts) — deliberately *not* `public/`, which Vite's dev server refuses to serve to a source-code import, so that arrangement worked in a release build and broke in dev.
  - **A scanned PDF is rasterized only after the text layer comes back empty** (`src/lib/pdf-ocr.ts`). Separate module from `pdf-text.ts` on purpose: that one turns rendering, fonts and images *off* because a text layer needs none of them, and rasterizing needs the exact opposite — one function with a flag would mean the hardened path and the rendering path sharing a config. OCR costs seconds of CPU per page, so it is never on the fast path; pages are drawn on a white fill (scans are often transparent) and capped at 20.
  - **Both memory sections share one character budget** (`MEMORY_PROMPT_CHARS` in blob-tools.ts — one constant, spent on shared facts first, remainder to the Blob's own). `MEMORY_LIMIT` caps the *count* per scope but not the length, and Ollama answers an over-long prompt by silently truncating it — costing the conversation, not the memories. User-scope facts render *above* the Blob's own (they change less often, so more of the cached prefix survives a Blob-scope write), and only the Blob's own are numbered, because the intent router addresses those by position (`forget` → "[2]").
  - **The keychain is probed lazily and once per session** (`configureTinfoilFromKeychain` memoization): a keychain read can prompt for the device password, so nothing may touch it unless a `tinfoil:` model is selected or the user acts (model picker open, Settings save with `force`). That caps prompts *within* one launch — the prompt *per rebuild* is macOS, not the app: a keychain item's ACL is keyed to the creating binary's code-signature hash, and `tauri dev` links a fresh ad-hoc signature every build (`Signature=adhoc`, `TeamIdentifier=not set`), so each rebuild is a new program and "Always Allow" can never stick. So **debug builds never touch the keychain at all**: secrets go through a process-local map (`mod dev` in `secrets.rs`, `#[cfg(debug_assertions)]`), **on by default** — it was opt-in on a non-empty `TINFOIL_API_KEY`, which meant an empty `.env.local` silently restored password prompts on every hot rebuild. Set `TINFOIL_API_KEY` in the gitignored `.env.local` (the `tauri:dev` script sources it) to seed that map so Tinfoil works in dev; empty just means dev starts keyless. `BLOBBIES_DEV_KEYCHAIN=1` opts back into the real keychain when the keychain path itself is what you are testing. Release always uses the keychain; a stable Developer ID signature is what makes the ACL stick for real users.
  - Every field the intent mapping reads is `required` in the schema — optional `memory_number` was omitted by the model on every delete (grammar-legal, mapping discarded it, forgets went 0/3). Unused fields are emitted as 0 and ignored.
  - Structured-output schemas must never carry `maxLength` — a grammar cap truncates the model mid-word; enforce length in the prompt.
  - **Every** Ollama call (chat, router, reconcile, forced-configure) pins the same `num_ctx: 16384` — Ollama's scheduler deep-equals runner options and reloads the whole model (dumping the KV cache) on any mismatch, so one call without it thrashes the runner twice per message.
  - Every call sends `keep_alive: "30m"` — the 5-minute server default unloads an idle model, costing a cold reload plus a from-scratch prefill on the user's next message. The other half of the deal: `ollama_unload_on_exit` in `commands.rs` runs `ollama stop <model>` on `RunEvent::Exit`, and `changeModel` in `App.tsx` calls `unloadOllamaModel` on the outgoing model when the user switches in the dropdown — otherwise Ollama keeps both resident side by side. Change any of the three only with the others in mind.
  - No clock in the system prompt — prefix caching is exact-match, so a minute-level timestamp there re-prefills the entire transcript every turn. The clock is appended to the newest user message via `timeNote()`; history is capped by `trimHistory()` in block trims (not a sliding window) so the cached prefix stays byte-stable between trims.
- **Only Blob-scope memories are written automatically.** The intent router has no notion of the `user` scope; promotion between scopes is a manual per-row toggle in `MemoriesSection` (`DetailPanel.tsx`). Teaching the classifier a second scope is a retune with sim cost, and the roadmap's stated gap was visibility, not automatic promotion.
- **The search palette indexes on open, not per keystroke** (`src/lib/search.ts` + `SearchModal.tsx`; the sidebar's Search "field" is the button that opens it). `buildIndex` walks every Blob's transcript, home folder and routines once into flat rows; typing only filters them. The per-Blob reads are deferred until a query or one of the deep tabs (messages/files/links/routines) asks, because the app hydrates transcript+routines for the *open* Blob only — those tabs would otherwise silently under-report every other Blob. Non-All tabs render one 25-row page and grow on scroll, so a Blob with 500 links never mounts 500 rows. Two rules that are containment, not polish: link rows accept `http(s)` only (a row hands its URL to the OS browser, so `file:`/`javascript:` must never become a clickable row), and a message row's title is a truncated one-line copy while `haystack` keeps the full text for matching. The Groups tab lists group chats by name and members; group *messages* are not indexed, because unlike a Blob's transcript there is no per-Blob read that would reach them. Usage/billing is deliberately absent from the actions: local inference has no bill. **Link rows cannot actually open yet**: `opener:allow-open-url` in `capabilities/default.json` allowlists four docs hosts, so `openExternal` rejects everything else — the same pre-existing limit that makes transcript links inert (`ExternalLink` swallows it identically). Widening that scope is a deliberate security decision, not a bug fix.
- **A table renders as its own bubble, never inside one** (`src/lib/markdown-blocks.ts` → `TextBubble`). A bubble hugs its text and `.message-line` caps it at 72% of the pane, which squeezed columns until a "Date" header wrapped to "Dat/e". `splitMarkdownBlocks` cuts an agent reply at each GFM table, so one message can be several stacked bubbles. The splitter tracks code fences (a table in a ``` block is sample text, not a table) and requires the delimiter row, so prose containing a pipe stays prose. Blocks are keyed by start line, not index — a streaming reply appends, so an earlier block's start never moves. Table CSS is row rules only, not a full grid: vertical borders fight columns the eye already reads from alignment. Cells are `white-space: nowrap` and the card scrolls sideways — wrapping is what squashes one long column into a two-line block beside one-line rows. A table bubble keeps the same 72% cap as every other bubble (a table is not a reason for one message to outgrow its neighbours); the columns that do not fit are reached by scrolling the card. `.bubble-table` needs `min-width: 0` for that: the inner table is `max-content`, and a flex item's default `min-width: auto` refuses to shrink below its content, so the card grew to the table's full width and the overflow never engaged. The selector is the doubled `.bubble.bubble-table` — `.bubble` is declared *later* in App.css at equal specificity, so a single class silently loses the padding cascade and nothing applies. Its bottom padding is the scrollbar's strip: macOS overlay scrollbars have zero layout thickness and paint over the bottom of the scroll box, i.e. across the last row's text.
- **Sidebar placement is drag-driven** (`src/lib/useBlobDrag.ts` + `Sidebar.tsx`). Pointer events, not HTML5 drag-and-drop, which gives no usable drag image in a webview; a 6px threshold keeps a click a click, and `consumeClick()` stops the click that ends a drag from also selecting the row. Drop zones are `data-drop` attributes hit-tested with `elementsFromPoint`, so the floating tile must stay `pointer-events: none` or it becomes its own target. Pinned Blobs leave the list for the avatar tray at the top; the empty tray only exists mid-drag, since that dashed "Drag here to pin" is the only thing teaching the gesture. Motion is on `--ease-squish` (an overshoot curve) throughout — tray unfurl, tile lift/land, press-squash, target squish — because the Blobs are soft and a hard stop reads as broken; the floating tile animates `scale` only, never `left`/`top`, which are set per-frame from the pointer and would lag. Group *names* now live in the `groups` store slice (migrated once from the old `pref:sections` localStorage list, dropping empty leftovers still called "New section"), but a Blob's `section` is a roster field — so a name that is not a current group reads as ungrouped, which is what lets a group be removed without touching the Blobs that were in it (only an empty one offers the control, and its transcript stays on disk). Sections themselves reorder on the *same* `useBlobDrag` hook (a second instance, keyed by section name): a section takes the place of whichever group it lands on, dropping on the always-topmost ungrouped run means "move to the top", and the header's name button is one control where a drag reorders and a plain click *opens the group's chat* (`consumeClick()` separates them, exactly as on a row) — collapsing moved to its own chevron button once the name became a conversation. That chevron and the remove `×` are both absolutely positioned at the same right-edge coordinates so they crossfade in place, and the name button spans the full header width so its hover fill lines up with the rows below. A shut section's rows are collapsed, never unmounted — the `<li>` keeps its `data-drop`, so a Blob can still be dropped on the header, and that drop re-opens the section rather than appearing to swallow the Blob. The collapse is the compose slot's `0fr→1fr` grid track (plus a `-4px` margin to eat the group gap), because `height: auto` cannot be transitioned; the rows carry `inert`, which is what keeps them untabbable and out of the a11y tree while they are shrinking. `hidden` was tried and is wrong twice over: it cannot animate, and `[hidden]{display:none}` is only in the *UA* sheet, so `.agent-group-rows`'s own `display: flex` silently beat it — in the browser only, since jsdom honours the attribute directly and the test passed while the app kept showing every row. Collapsed names persist in `pref:sectionsCollapsed`, and removing a group drops its flag there too — names repeat (an untitled group is "New Group"), so a leftover flag would make the next one of that name open up already shut.
- **A group chat is a sidebar group with a transcript** (`src/lib/groups.ts`). Membership *is* the Blob's `section` field — there is no member list — which makes the group **name** a key: `changeGroups` is the single write point and enforces case-insensitive uniqueness there (create suffixes, rename refuses, migration dedupes), because two groups sharing a name would each claim the other's Blobs and the sidebar's reorder — which maps name back to group — would silently drop one. `membersOf` reads `agentsRef`, and `sendToGroup` re-reads membership **per speaker** rather than using the list captured at send time: an exchange runs several turns and may start long after the message, so a Blob dragged out, hidden or deleted in between must not speak for a group it has left (test: “drops a member removed from the group while the exchange is running”). The group's name is re-read the same way, so a rename mid-exchange does not tell later speakers they are somewhere that no longer exists; so renaming a group must rewrite every member's `section` in the same commit (`renameGroup` in App.tsx) or the group empties itself, and the group's `id` exists only to key its own transcript slice (a group name is user text and can never be a path component). Blobs in no group render above the groups, as before. Both creation paths live in the **New** palette (`ComposePane`): the sidebar list has no add button, and a group is joined by dragging a Blob's row into it. Who is *brought in*, in order of authority: `addressedResponders` — `@Name` or `@everyone` or a reply to a Blob's message, all certain and free — else the `pickResponders` router picks by job (name + title + description of the group's members only, plus the last few transcript lines so "and what did that cost?" is routable), else (router unreachable only) everyone. **Not** "everyone by default": members answer **in series** on one local model, so a group where all six answer every "thanks" is a group nobody keeps; `MAX_GROUP_MEMBERS` (6, enforced at drop time) is the same cost cap. **Being picked is an invitation, not an obligation.** A responder may answer with the bare token `PASS` (`isPass`, which also accepts "PASS — reason"); its bubbles are then taken back off the screen, so the user never reads the word. Only a Blob the router *chose* may pass; anyone the user addressed — `@Name`, `@everyone`, or a reply (`namedResponders`) — owes an answer. `@everyone` addresses **every** member and none may pass: asking the room and getting silence is not an answer. The measured risk is a chorus (three members answering “210 euros” in turn), and the cure is the prompt — an addressed Blob owes a reply and must add its own angle rather than restate a colleague's — not the app deciding the user did not mean what they typed. A Blob that is picked by the router and then passes gets a “X had nothing to add” line, because its thinking blob already appeared and vanishing without a trace is indistinguishable from a crash. A router pick of *nobody*, or everyone passing, writes an event line — an app where nothing at all happens is indistinguishable from a broken one. Every clause here is a measured fix, and the prompt is a balance that breaks in both directions: letting a Blob pass because "this needs a colleague's job" had qwen3.5:9b duck real work (both members passing on "get the sources, then write it up"), while `@everyone` obliging each member had all three answer "210 euros" in turn, each having just read the one before it say exactly that. The PASS rule is therefore scoped to redundancy and social noise only, stated *first* in the group section (buried mid-section, 2b ignored it), and repeated in App's trailing focus line — the last thing the model reads, where a bare "answer the user" otherwise overrode it. A responder can then pull in **one** teammate via `handoffTarget`, which requires the `@Name` to *open a sentence*: `pnpm sim:group` caught a Blob answering a question with "…I've also noted that @Scout will not be attending, and @Quill has confirmed", waking two teammates to say nothing — the chorus through the side door. Each Blob speaks at most once per exchange, so it always terminates. Residual, measured on qwen3.5:2b: a small model sometimes *opens* its reply with `@Teammate` as a form of address, which is indistinguishable from a hand-off and costs one wasted turn — self-limiting, and qwen3.5:9b addresses the user instead. Tighten the prompt before adding a code rule; the guard already went from "every passing mention" to "sentence-opening only". Each member is a normal `"chat"`-scope turn (a group is a conversation, not a routine, so the tuned catalog stays), streamed into the group's transcript while runs, usage and the home folder stay the speaking Blob's own; other members' lines enter the request as **user** messages labelled `[Name]:`, since as assistant messages a Blob reads them as its own earlier answers. The prompt names the Blob's own handle (`You are @Name`) and lists the others' — without it a Blob cannot tell whether it was spoken to, and a real transcript showed the second Blob replying to the *first* while the user who said "Hi all" was left out. App appends a trailing focus line naming the user's message, because by the time a later member runs, the newest message is a colleague's reply and models answer the newest thing. `@mentions` render in the mentioned Blob's own avatar colour (`lib/mentions.ts` + `Mention.tsx`), in user and agent bubbles alike `@mentions` render in the mentioned Blob's own avatar colour (`lib/mentions.ts` + `Mention.tsx`), in user and agent bubbles alike — the highlight uses the same whole-name, word-bounded rule as `parseMentions`, because colouring a mention that wakes nobody teaches the user the wrong thing about who is being addressed. Two colours ride on the element (`--mention-on-light` / `--mention-on-dark`, the pale and deep ends of the Blob's gradient) and CSS picks by theme: the theme can flip without React re-rendering the transcript, so resolving it in JS would leave every existing bubble wrong. Inside a Blob's markdown it is a rehype plugin (`rehype-mentions.ts`) rather than a string replace — react-markdown refuses raw HTML on purpose, so the span is a node we build and the colours come from the roster, never from model text. The looped shimmer is `background-clip: text` over the flat colour, so it degrades to a plain coloured mention under `prefers-reduced-motion` or without that property. The composer's @-menu lists the group's members and completes on Enter/Tab; its `MENTION_TOKEN` allows **spaces** in the typed prefix, because real Blob names have them ("Social Blob") and stopping at the first space made the menu vanish halfway through the very name it completes — what closes it instead is having no match left. Nothing is highlighted until a prefix is typed — a pre-selected first option reads as a choice already made — so Enter against a bare “@” sends rather than picking for you (Tab always completes). The composer draws the draft twice: a `.composer-mirror` under a transparent textarea, so mentions carry their colour while being typed. The mirror must match the textarea's padding, font, line-height and wrapping exactly, and copies its `scrollTop`; the wrapper carries `data-flip` in the textarea's place so the composer's FLIP glides see the same box. A group carries its own `unread` flag (set when a Blob speaks while the group is off screen, cleared on open) because the words land in the group's transcript and no member's unread dot can stand in for them; its sidebar dot pulses on the same 3.6s beat as the mention shimmer, and is announced through the header button's own `aria-label` — inside a button a labelled child is concatenated into the accessible name, which read as “LaunchUnread messages in Launch”. The per-Blob dot badges the avatar's corner rather than trailing the snippet: at the end of a variable-length line it landed somewhere different on every row, and it vanished entirely in the collapsed rail, which is exactly when it is the only signal left.
- **Memories in a group are the room's, written once, before anyone speaks.** One `routeIntent` per user message in `sendToGroup`, applied by `applyGroupIntent` to the **shared** `user` scope; every responder then runs with `streamBlobTurn({ intent })`, which skips its own router and its own write. Per-responder routing would have each Blob classify the same sentence and save a private copy, each reconciled against a different list — six drifting versions of one thing the user said once. `change_job` is dropped in a group: "be my writing coach instead" has one subject in a 1-to-1 chat and none in a room, so reconfiguring whoever happened to answer would be a silent destructive guess — enforced twice, since `applyGroupIntent` declining to apply it is not enough on its own: `streamBlobTurn` also refuses to derive `forceConfigure` from a *passed-in* intent, which would otherwise rewrite that Blob's job anyway. A classifier failure leaves `intent` undefined and each responder falls back to routing for itself: noisier, never silent. Attachments are per-Blob by construction (saved in a home folder, inlined at turn time), so a group composer takes no files at all — button *and* input unmounted, and `addFiles` refuses drops and pastes, since a chip that is silently discarded on send is worse than no button. The whole exchange is **one** queued turn (the router runs before the first speaker is known, and a later speaker only appears once an earlier one has spoken), and with no model configured only one member speaks — six copies of "pick a model in Settings" is one app-level problem shouted six times. `sentByAgent` is keyed by *conversation*, not Blob (`group:<id>`), and writes go through `mutateSent` — the ref is assigned synchronously because queued members run back to back and a render-lagged ref would hand member two the transcript without member one's reply.
- **Blob names are unique, case-insensitively** (`uniqueBlobName` in data/agents.ts, applied in `createBlob`, `duplicateBlob`, `rosterAccess.create` and — the choke point for every rename — `updateBlob`). The name is the addressing key: `@Scout` resolves to the first match, so a second Scout would be permanently unmentionable with no way for the user to say which they meant. Collisions get a numeric suffix, trimmed to fit `MAX_BLOB_NAME_LENGTH` *with* the suffix so a long name is not sliced back onto the name it is avoiding. `everyone` is reserved for the same reason (`@everyone` addresses the room). Uniqueness is settled on **blur**, not per keystroke (`commitName` on `updateBlob`, sent by SettingsPanel's `onBlur`): the name field is controlled, so suffixing as the user types turns "Scout Two" into "Scout 2" the moment it passes an existing "Scout", and trimming strips the space before the second word can be typed. A name blanked and left blank keeps the old one — an unnamed Blob is unaddressable and unreadable in the sidebar.
- **Blob lifecycle: one cap, and hiding is always reversible.** `MAX_BLOBS` (25) lives in `src/data/agents.ts`, not `lib/blob-tools`, because `Sidebar`/`CreatorPane` must not statically import that module (startup-bundle budget) — it gates the creator's submit, Duplicate, and `spawn_blob` alike. It is a blast-radius number for one machine (every Blob is a scheduler participant and turns are serial against one local model), not a hosted-account number. **Hide must always have a way back**: a hidden Blob (`hidden: true`, filtered out of the sidebar list) is reachable only through the "Show hidden chats" group at the bottom of the list, whose rows are deliberately non-draggable and whose `<li>` carries no `data-drop` — dropping a hidden row into a section would write a `section` on a Blob that stays invisible. **Duplicate copies the job, not the history**: profile fields (name/title/description/instructions/avatar) and routines carry over; memories, `usage`, the transcript and the home folder do not. Copied routines get fresh ids, no run history, and a re-armed `nextRunAt` (`nextFireTime(schedule, Date.now())`) — `armRoutines` only runs at startup, so an unarmed copy would silently never fire; the copy therefore opens **Edit Profile**, not the conversation, so renaming precedes the first fire. Delete is not permanent (`store.rs` moves the Blob to `trash/` with a 30-day TTL) and the dialog copy must not claim otherwise. The tone/shape grids are one shared `AvatarPicker` used by both surfaces, so its radios take a `group` prefix (two mounts would otherwise be one radio group) and its fieldsets must stay `flex-wrap: wrap` — ten swatches are wider than the 322px detail panel.
- **The data root is `~/.blobbies`**, not `~/Library/Application Support/com.blobbies.app/data` (`store::data_root`) — one path a user can type, back up or delete without knowing the bundle id, and the folder the onboarding permissions step names. `migrate_legacy_root` brings a pre-move install across, once, from `startup_maintenance` — not from `data_root`, which every store read and write resolves through and must stay a side-effect-free path lookup. Tauri's `setup` hook runs it before the webview can issue a command. **Copy, never move**, into `~/.blobbies.migrating` and only then renamed into place, so an interrupted copy leaves neither a half-populated root that the `root.exists()` check would mistake for a finished migration, nor a user without their old data. The legacy tree is deliberately left on disk. Symlinks inside it are skipped rather than followed (`file_type` does not traverse), so a link cannot pull files in from outside.
- **Onboarding is a fixed overlay, not a route** (`src/components/Onboarding.tsx`, rendered last in App so it covers everything). Five steps — welcome, what a Blob is, permissions, Tinfoil, plugins — with the step index as the only flow state, and it **ends on the app's own `CreatorPane`** rather than carrying a creator screen of its own: `finishOnboarding` sets `mode` to `creator` explicitly, because the empty-roster fallback that renders the creator does not apply on a dev-toggle replay where Blobs already exist. A second creator inside the flow would be a copy of that screen drifting away from it, with its own name field outside `uniqueBlobName` and the `MAX_BLOBS` cap. The plugins step edits the app's real `installedPlugins`, so there is no second list to reconcile. `pref:onboarded` is written on the way out, before the creator is shown — the flow is over once the user has seen it, not once they have named something. **The Tinfoil step validates a key's *shape*, and says only that.** There is no reachable check that a key works: `/v1/models` is public (200 for any key, measured), `configureTinfoilFromKeychain` only checks a key exists, and an authenticated `/v1/chat/completions` returns 401 through a plain fetch even for a good key — auth lives in the attested client. A network "check" here would reject valid keys, so the field catches paste damage (quotes, `NAME=` prefix, embedded whitespace, truncation) and the copy promises storage only, deferring the real answer to the first Tinfoil model use. Do not "improve" this into a fake verification. The step is skippable and writes nothing when left empty. The trio of Blobs orbits on one CSS animation — shared anchor, `--phase` spreads them, an inner counter-rotation keeps faces upright, and `--orbit-r` is an `@property` length so the collapse to the corners can transition while the rotation runs; reduced motion drops the animation and places them statically. **The notification prompt is on the Allow button, never on mount** — same rule as `notify`'s lazy request and the keychain probe: an OS prompt the user did not earn by acting is the mistake. `requestNotificationPermission` in `lib/notify.ts` exists only for that button. `pref:forceOnboarding` (Settings → General → Developer) replays the flow now and on every launch, which is how the screens are worked on after the first run; `VITE_ONBOARDING=1 pnpm tauri dev` does it for one launch without writing anything, which is the way back in when the flag is already set and the webview owns the storage. That branch is guarded by `import.meta.env.DEV`: Vite *inlines* env vars at build time, so unguarded a stray `VITE_ONBOARDING=1 pnpm build` would ship onboarding-on to every user. Tests: `src/test/setup.ts` seeds `pref:onboarded` for every suite, because otherwise the flow covers the app every other test asserts — and any test that stubs `localStorage` wholesale must seed it too.
- **CSP `connect-src` carries the Tinfoil hosts.** `https://*.tinfoil.sh` (atc attestation + inference + per-enclave domains) and `https://tuf-repo-cdn.sigstore.dev` (Sigstore TUF root for the verifier) in `src-tauri/tauri.conf.json`. Tinfoil uses webview fetch, not the tauri http plugin, so `capabilities/default.json` is unaffected.
- **`capabilities/default.json` denies private ranges one glob per octet** — Tauri URL globs can't express ranges, so Docker 172.16–172.31 and CGNAT 100.64–100.127 are enumerated entry-by-entry under `http:default`. Removing one silently reopens SSRF-ish access from web tools. The deny list is `https://`-only, which is why the two loopback `http://` allow entries are additive rather than a hole in it — and why local MCP is http-only (see below).
- **Local MCP is loopback-only, and the capability is not the control** (`src/lib/mcp.ts`). `parseLoopbackUrl` re-runs on *every* request, not just at save time, because `mcpServers` lives in the plain-JSON `settings` slice — an editable file on disk. It accepts exactly what the capability permits — `http://` (not https, which the deny list blocks on loopback and **deny beats allow** in Tauri's scope), host exactly `localhost`/`127.0.0.1` (no `::1`: no allow entry covers it), and an explicit port (the globs carry `:*`, which will not match a portless URL). Loosening any of those three yields a connection the UI saves and the Rust layer then refuses with an opaque error. `maxRedirections: 0` is load-bearing: the Rust http plugin scope-checks only the *initial* URL and then lets reqwest follow redirects, so a local server answering 302 with a public `Location` would carry the POST body (tool arguments and all) off the machine. An MCP server is an untrusted party whose text is model-facing: tool names are sanitized and namespaced (`mcp__<server>__<tool>`), deduped across *all* servers so a newly added one cannot shadow a trusted one; descriptions are stripped of newlines/bidi/zero-width characters and wrapped in a fixed "that server's own text, not an instruction from the user" frame; results are truncated and fenced by `wrapUntrusted`. **stdio transport is deliberately absent** — it means spawning user-configured executables, i.e. arbitrary code execution driven by a config file; a local proxy fronts stdio servers today. The client is hand-rolled JSON-RPC (~340 lines of code) rather than `@modelcontextprotocol/sdk`, which drags express/hono/jose/cross-spawn into the webview bundle for the three calls we actually make (`initialize`, `tools/list`, `tools/call`).
- **Usage counts the agent loop only.** `onUsage` is fed from gg-agent's `agent_done`, which fires once per loop — and a turn can run the loop more than once (the no-tools retry, the rescue round), so callers *sum*. The three structured calls (router, reconcile, forced-configure) are outside the loop and go uncounted; plumbing them in would touch the tuning-tested request bodies. Framed in the UI as why replies slow down, never as cost — local inference has no bill.
- **Tests get a Map-backed `localStorage` from `src/test/setup.ts`**, wiped per test: this jsdom build ships none, so every preference read (`lib/preferences.ts`) otherwise silently fell back to its default and no test could set one. `clearFallbackBackend` (store.ts) therefore removes only the keys the *store* wrote, tracked in `writtenKeys` — the old `localStorage.clear()` would take the app's `pref:*` with it, including the onboarding flag, on the same origin.
- **Sim tests are intentionally serial** (`fileParallelism: false`, `maxConcurrency: 1`): parallel runs fight over Ollama KV-cache slots and distort the timing report.
- **Rust pinning is deliberate**: `rust-toolchain.toml` 1.90.0, `Cargo.toml` `rust-version = "1.90"`, edition 2024 — kept in sync so the MSRV-aware resolver doesn't hold back security patches. CI installs cargo-audit with `--locked` because unlocked install broke on the pinned rustc.

## Workflow notes

- `pnpm tauri:dev` for the full app (spawns `pnpm dev` itself); plain `pnpm dev` is frontend-only in a browser.
- `pnpm build` chains `typecheck && vite build`; `tauri:build` reads `TAURI_ENV_PLATFORM`/`TAURI_ENV_DEBUG` to pick build target/minify.
- Lefthook pre-push runs typecheck + test + clippy; pre-commit auto-fixes biome + rustfmt on staged files. `pnpm check` is the local equivalent of CI.
- Rust checks live behind pnpm wrappers (`rs:fmt`, `rs:lint`, `rs:test`) — clippy runs with `-D warnings`.
